# داشبورد تحلیل بازار پلتفرم‌های هوش مصنوعی ایران

داشبوردی برای پیگیری تعداد نصب، امتیاز و تعداد نظرات اپ‌های چت‌بات هوش
مصنوعی در دو مارکت ایرانی (کافه‌بازار و مایکت). این نسخه با Node.js و
Express اجرا می‌شود، روی یک URL برای همه در دسترس است، و دیتابیس را روی
دیسک سرور نگه می‌دارد.

## ساختار پروژه

```
.
├── server.js              # سرور Express — API + سرو فایل‌های استاتیک
├── lib/
│   └── scraper.js         # استخراج آمار از کافه‌بازار/مایکت (cheerio)
├── public/
│   └── index.html         # خودِ داشبورد (کلاینت)
├── data/
│   ├── db.json             # دیتابیس فعلی: periods / platforms / data / sources
│   └── sources.json        # نگاشت هر پلتفرم به لینک صفحه‌اش در دو مارکت
├── package.json
├── ecosystem.config.js     # تنظیمات PM2
├── .gitignore
└── README.md
```

## پیش‌نیازها

- [Node.js](https://nodejs.org) نسخه‌ی ۱۸ به بالا (شامل npm)
- (اختیاری، برای اجرای دائمی) [PM2](https://pm2.keymetrics.io):
  ```bash
  npm install -g pm2
  ```

## نصب و اجرا

```bash
cd node-repo
npm install
npm start
```

اگر همه‌چیز درست باشد، این پیام دیده می‌شود:

```
داشبورد روی http://localhost:3000 در حال اجراست.
```

آدرس را در مرورگر باز کنید (حتماً با `http://` — نه با دابل‌کلیک روی خودِ
فایل `index.html`، چون در آن حالت درخواست‌های API کار نمی‌کنند).

برای اجرا روی پورت دیگر:

```bash
PORT=8080 npm start        # لینوکس/مک
set PORT=8080 && npm start # ویندوز (cmd)
```

## اجرای دائمی با PM2

برای اینکه سرور بعد از بستن ترمینال هم روشن بماند و در صورت کرش خودش
دوباره بالا بیاید:

```bash
pm2 start ecosystem.config.js
pm2 save          # وضعیت فعلی را ذخیره می‌کند
pm2 startup       # دستوری که چاپ می‌کند را اجرا کنید تا با بوت سرور هم بالا بیاید
```

دستورات مدیریتی مفید:

```bash
pm2 status                        # وضعیت پروسه
pm2 logs ai-apps-dashboard        # دیدن لاگ‌های زنده
pm2 restart ai-apps-dashboard     # ری‌استارت بعد از هر تغییر در کد
pm2 stop ai-apps-dashboard
```

اگر می‌خواهید داشبورد پشت یک دامنه و با HTTPS واقعی در دسترس باشد، یک
ری‌ورس‌پراکسی مثل Nginx یا Caddy جلوی همین پورت (پیش‌فرض 3000) بگذارید.

## استفاده از داشبورد

1. آدرس سرور را باز کنید و با `admin` / `admin` وارد شوید.
2. برای افزودن دستی یک دوره‌ی جدید: **«➕ ثبت داده دوره جدید»** → لینک هر
   اپ در کافه‌بازار/مایکت را باز کنید → سه عدد (نصب، امتیاز، تعداد نظرات)
   را در باکس‌های همان ردیف بنویسید → **«افزودن دوره به داشبورد»**.
   این کار به‌طور خودکار روی سرور هم ذخیره می‌شود.
3. **«↻ بارگذاری JSON»** یک فایل کامل دیتابیس (خروجی «⬇ دانلود دیتابیس»)
   را جایگزین دیتابیس فعلی می‌کند — برای بازگردانی پشتیبان یا انتقال داده
   از یک نسخه‌ی دیگر از همین داشبورد.
4. **«⬇ دانلود دیتابیس»** یک نسخه‌ی پشتیبان از دیتابیس فعلی روی کامپیوتر
   شما ذخیره می‌کند.

## دکمه‌ی دریافت خودکار داده (اسکرپ)

روی **«🔄 دریافت خودکار از فروشگاه‌ها»** کلیک کنید:

1. سرور تمام پلتفرم‌ها را (هرکدام هم‌زمان از کافه‌بازار و مایکت، حداکثر ۳
   درخواست هم‌زمان، با تایم‌اوت ۱۲ ثانیه‌ای برای هر درخواست) اسکرپ می‌کند.
   این کار ممکن است چند دقیقه طول بکشد.
2. نتیجه به همراه فهرست مواردی که خطا داده‌اند به فرم «ثبت داده دوره
   جدید» منتقل و از قبل پر می‌شود.
3. مقادیر خالی یا مشکوک را دستی تصحیح کنید، برچسب دوره را بنویسید، و
   **«افزودن دوره به داشبورد»** را بزنید.

> ⚠️ کافه‌بازار و مایکت اسکرپ خودکار را در `robots.txt` ممنوع کرده‌اند و
> ممکن است IP سرور شما را هم در آینده مسدود کنند. اگر تعداد زیادی خطا
> دیدید (یا همه‌چیز `null` برگشت)، ساختار HTML یکی از دو سایت احتمالاً
> عوض شده — الگوهای `extractCafebazaar` / `extractMyket` را در
> `lib/scraper.js` باید به‌روزرسانی کرد. لاگ سرور (`pm2 logs`) پیام خطای
> دقیق هر مورد را نشان می‌دهد.

## افزودن یا حذف یک پلتفرم

سه جا باید هماهنگ ویرایش شوند (یا مستقیم در `data/db.json`، یا با
بارگذاری یک فایل کامل جدید از طریق «↻ بارگذاری JSON»):

- `platforms` — نام و نوع (داخلی/خارجی) پلتفرم
- `data` — رکورد هر پلتفرم در هر دوره
- `sources` — لینک کافه‌بازار/مایکت آن پلتفرم

فایل `data/sources.json` هم باید همزمان به‌روزرسانی شود تا دکمه‌ی اسکرپ
هم با لیست جدید هماهنگ بماند.

## مستندات API

| متد | مسیر | توضیح |
|---|---|---|
| `GET` | `/api/data` | خواندن کل دیتابیس فعلی |
| `PUT` | `/api/data` | جایگزینی کامل دیتابیس (بدنه باید شامل آرایه‌های `periods`، `platforms`، `data` باشد) |
| `POST` | `/api/scrape` | اجرای اسکرپ روی همه‌ی پلتفرم‌ها؛ خروجی: `{ label, values, errors }` |

همه‌ی خطاها (شبکه، HTML غیرمنتظره، داده‌ی نامعتبر) با کد وضعیت مناسب
(۴۰۰ یا ۵۰۰) و پیام JSON خوانا برگردانده می‌شوند؛ هیچ‌کدام پروسه‌ی سرور
را پایین نمی‌آورند.

## نکات امنیتی

این نسخه روی یک URL عمومی قرار می‌گیرد، پس این نکات مهم‌اند:

- ورود فعلی (`admin`/`admin`) فقط یک گیت ساده‌ی سمت کلاینت است، **نه
  احراز هویت واقعی** — هرکسی که کد صفحه را ببیند می‌تواند دورش بزند.
  برای استفاده‌ی واقعی روی اینترنت باز، یکی از این دو را اضافه کنید:
  - Basic Auth روی Nginx/Caddy جلوی پورت سرور، یا
  - یک میان‌افزار احراز هویت واقعی در `server.js` روی مسیرهای `/api/*`
    (به‌خصوص `PUT /api/data`، چون می‌تواند کل دیتابیس را بازنویسی کند).
- اگر جلوی سرویس یک ری‌ورس‌پراکسی است، `proxy_read_timeout` آن را حداقل
  روی ۱۲۰ ثانیه بگذارید — چون `/api/scrape` می‌تواند چند دقیقه طول بکشد.

## عیب‌یابی

**«command not found» یا صفحه باز نمی‌شود:**
مطمئن شوید `npm install` بدون خطا تمام شده و با `npm start` سرور واقعاً
در حال اجراست (نه اینکه فایل `index.html` را مستقیم دابل‌کلیک کرده‌اید).

**نمودارها/داده‌ها خالی است:**
از مسیر `http://` وارد شوید، نه `file:///`. کنسول مرورگر (F12) را چک
کنید — اگر خطای شبکه به `/api/data` می‌بینید، یعنی سرور بالا نیست یا روی
پورت دیگری اجرا شده.

**اسکرپ همیشه خطا می‌دهد:**
طبیعی است اگر IP سرور شما مسدود شده باشد یا ساختار سایت مقصد تغییر کرده
باشد؛ همچنان می‌توانید از فرم «ثبت داده دوره جدید» به‌صورت دستی داده
وارد کنید.
